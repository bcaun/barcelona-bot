# ТЗ: Telegram-бот и мини-апп игра для barcelona.ru

Документ для Claude Code. Положить в корень нового репозитория как `SPEC.md`, первой командой дать:
«Прочитай SPEC.md целиком. Задай вопросы, если что-то противоречит. Затем выполни Фазу 0 и остановись».

---

## 1. Контекст

- **barcelona.ru** — агентство недвижимости в Барселоне для русскоязычных покупателей и инвесторов. Есть английская версия и домен barcelona-estate.com.
- Цель: Telegram-воронка «канал → бот → заявка», игра — источник охвата и вирусности.
- Канал (контент) делается вручную и в объём ТЗ не входит. Бот и игра должны уметь проверять подписку на канал и вести в него.
- Владелец не программист по серверам: все инструкции по запуску и деплою — пошагово, простым языком, с готовыми командами для копирования.

## 2. Состав работ по фазам

| Фаза | Что | Результат |
|---|---|---|
| 0 | Скелет проекта | Бот отвечает на /start, конфиг, БД, i18n, логирование, тесты, деплой-инструкция |
| 1 | Калькулятор стоимости покупки и владения | Рабочий расчёт + сбор заявки |
| 2 | «Проверить объект» (Catastro) | Данные объекта по RC / адресу / геоточке + флаги регулирования |
| 3 | Мини-апп «Знаешь ли ты жильё в Барселоне?» (квиз) | 25 вопросов, 3 жизни, приз — бесплатная nota simple, рейтинг (изменено 2026-11-06) |

После каждой фазы — остановка, краткий отчёт владельцу (что сделано, как проверить, что дальше). Следующая фаза — только после подтверждения.

## 3. Общие требования

### 3.1. Стек

- Python 3.12, **aiogram 3.x** (бот, long polling).
- **FastAPI** — API мини-аппа (Фаза 3), в том же репозитории.
- **SQLite** через SQLAlchemy 2.x + Alembic; схема без SQLite-специфики, чтобы потом переехать на PostgreSQL сменой строки подключения.
- httpx — внешние HTTP-запросы (Catastro).
- Фронтенд мини-аппа: Vite + TypeScript, без тяжёлых фреймворков (допустим Preact). Telegram WebApp SDK (`telegram-web-app.js`).
- Docker Compose: сервисы `bot`, `api`, `cloudflared` (HTTPS для мини-аппа через Cloudflare Tunnel; изначально — `caddy`, заменён, т.к. порты 80/443 на VPS заняты). DNS — Cloudflare.
- Хостинг: VPS Hostinger (Ubuntu).

### 3.2. Структура репозитория

```
/app
  /bot          # хендлеры aiogram, клавиатуры, middlewares
  /core         # расчёты (чистые функции, без Telegram), модели, БД
  /integrations # catastro.py, telegram_channel.py
  /api          # FastAPI для мини-аппа
  /i18n         # ru.yaml, en.yaml
/config
  settings.yaml # не секретные настройки
  taxes.yaml    # ставки и пороги (см. 5.3)
  regulation.yaml # зоны, лицензии, тексты (см. 6.4)
/webapp         # фронтенд игры
/migrations
/tests
.env.example
docker-compose.yml
README.md
DEPLOY.md
```

### 3.3. Обязательные принципы

- Вся бизнес-логика расчётов — в `/core` как чистые функции с юнит-тестами. Telegram-слой только собирает ввод и показывает вывод.
- **Никаких ставок и порогов в коде.** Всё из `config/taxes.yaml` и `config/regulation.yaml`, у каждого значения — комментарий с источником и датой проверки.
- Секреты (токен бота, ID чатов) — только в `.env`. `.env` в `.gitignore`.
- i18n с первого дня: все тексты в `ru.yaml`/`en.yaml`, язык по `language_code` пользователя с ручным переключением. Английский можно заполнить позже, но ключи должны существовать.
- Денежные суммы — `Decimal`, округление до евро в выводе, формат `82 000 €`.
- Логи: structured (JSON) в stdout, уровень из `.env`. Ошибки внешних API не роняют бота — пользователь получает понятное сообщение.
- Под каждым расчётом — дисклеймер: «Расчёт ориентировочный и не является налоговой консультацией. Точную сумму подтвердит нотариус / гестор».

### 3.4. Данные и RGPD

- Пользователи бота — из ЕС в том числе, применяется GDPR / LOPDGDD.
- Хранить минимум: telegram_id, username, язык, дата первого входа, события (без текста переписки).
- Заявка (лид) — только с явным согласием: кнопка «Согласен на обработку данных» + ссылка на политику конфиденциальности (URL из `settings.yaml`).
- Контакт — через кнопку `request_contact` (телефон), либо по желанию просто username.
- Команда `/delete_me` — удаляет данные пользователя и его лиды. Указать в политике.
- Реквизиты оператора данных (юрлицо barcelona.ru) — поле `legal.controller` в `settings.yaml`, заполняет владелец.

### 3.5. Аналитика

- Таблица `events`: user_id, event_type, payload (JSON), source, created_at.
- Deep link-параметр `/start <source>` (например, `post_123`, `game`, `site`) пишется как источник пользователя и каждого лида — чтобы видеть, какие посты канала приводят заявки.

## 5. Фаза 1 — калькулятор стоимости покупки и владения

### 5.1. Сценарий диалога (пошаговый, инлайн-кнопки, с кнопкой «Назад» на каждом шаге)

1. Тип объекта: **Вторичка** / **Новостройка (от застройщика)**.
2. Цена покупки, € (число; принимать «450000», «450 000», «450k»).
3. Кадастровая референсная стоимость (valor de referencia), € — **необязательно**, кнопка «Не знаю». Если не указана — база = цена, с предупреждением, что налог считается от большего из двух значений.
4. Покупатель: **Частное лицо** / **Компания**.
5. Только для вторички, частного лица: «Покупка для постоянного проживания (vivienda habitual)?» → если да, проверка льготы 5% (см. 5.3): возраст ≤ 35, или многодетная/неполная семья, или инвалидность ≥ 65%; и доход (IRPF base) ≤ порога. Вопросы да/нет; если льгота не подходит — общая шкала.
6. «Покупатель владеет более чем 10 жилыми объектами в Испании или более 1 500 м² жилой площади (или это компания-крупный собственник)?» → если да, ставка grandes tenedores 20% (вторичка) с пометкой «исключения не учитываются — уточните у нас».
7. Ипотека: **Нет** / **Да** → доля кредита (% от цены, по умолчанию 60%).
8. Налоговый статус после покупки: **Резидент Испании** / **Нерезидент из ЕС/ЕЭЗ** / **Нерезидент вне ЕС**.
9. Для нерезидентов: кадастровая стоимость (valor catastral) из recibo IBI, € — необязательно.
10. Сдавать в долгосрочную аренду? **Нет** / **Да** → ожидаемая аренда в месяц, €.

### 5.2. Вывод

Сообщение из трёх блоков + кнопки.

**А. Расходы при покупке (единоразово)**
- Налог на покупку: ITP (вторичка) **или** IVA + AJD (новостройка) — сумма и как посчитано (с разбивкой по ступеням шкалы).
- Нотариус, реестр, гестория — диапазон «от–до» из конфига.
- Оценка (tasación) — если ипотека.
- Комиссия агентства для покупателя — из конфига (по умолчанию 0, скрывать строку при 0).
- **Итого сверх цены** и **итого с ценой**, плюс «нужно собственных средств» при ипотеке (цена − кредит + расходы).

**Б. Ежегодные расходы владения**
- IBI — если введена кадастровая стоимость, оценка по ставке из конфига; иначе строка «зависит от кадастровой стоимости, обычно ≈ X–Y % в год».
- Comunidad — пользователь не вводит, показывается как «по данным объекта».
- Для нерезидентов без аренды: IRNR на условный доход = valor catastral × коэффициент вменения × ставка (19% ЕС/ЕЭЗ, 24% вне ЕС). Без valor catastral — пояснение формулы без суммы.

**В. Аренда (если указана)**
- Валовая доходность = аренда × 12 / (цена + расходы при покупке).
- Налог на доход от аренды для нерезидентов: ЕС/ЕЭЗ — 19% с чистого дохода (упрощённо: доход минус IBI; детали — на консультации); вне ЕС — 24% с валового.
- Чистая доходность (упрощённая).
- Предупреждение: Барселона — зона напряжённого рынка, арендная ставка ограничена индексом; туристическая аренда не допускается (тексты из `regulation.yaml`).

**Кнопки под результатом:**
- 📩 «Подобрать объекты под этот бюджет» → лид типа `calc` со всеми параметрами расчёта.
- 🔁 «Пересчитать».
- 📢 «Наш канал».

**Подписка:** если `settings.calc.require_subscription: true`, блоки Б и В показываются только подписчикам канала; не подписанным — кнопка «Подписаться» и «Я подписался» (повторная проверка). По умолчанию `false`.

```yaml
    income_limit_irpf_base: 36000      # база IRPF минус личный и семейный минимум
    income_limit_extra_per_child: 14000 # для многодетных/неполных, за каждого ребёнка сверх минимума

  ajd: 0.015           # Каталония, общая ставка
  # Льгота AJD для покупателей до 36 лет (основное жильё) — заявлена с 27.06.2025;
  # включить после сверки с первоисточником
```

### 5.4. Тест-кейсы (обязательные юнит-тесты `/core`)

| Кейс | Вход | Ожидаемый налог |
|---|---|---|
| Вторичка, общая шкала | 800 000 € | 60 000 + 22 000 = **82 000 €** |
| Вторичка, общая шкала | 1 000 000 € | 60 000 + 33 000 + 12 000 = **105 000 €** |
| Вторичка, общая шкала | 2 000 000 € | 60 000 + 33 000 + 72 000 + 65 000 = **230 000 €** |
| Вторичка, льгота 5% | 300 000 €, возраст 30, доход 30 000 | **15 000 €** |
| Вторичка, льгота не проходит по доходу | 300 000 €, возраст 30, доход 40 000 | **30 000 €** |
| Вторичка, valor de referencia выше цены | цена 500 000, VR 550 000 | база 550 000 → **55 000 €** |
| Вторичка, крупный собственник | 400 000 € | **80 000 €** |
| Новостройка | 400 000 € | IVA **40 000 €** + AJD **6 000 €** |
| IRNR нерезидент вне ЕС | valor catastral 150 000, Барселона | 150 000 × 2% × 24% = **720 €/год** |
| IRNR нерезидент ЕС | valor catastral 150 000, Барселона | 150 000 × 2% × 19% = **570 €/год** |

Плюс тесты парсинга ввода («450k», «450 000 €», «abc» → ошибка с подсказкой).

**Приёмка Фазы 1:** все тест-кейсы проходят; диалог проходится до конца по всем веткам; «Назад» работает на каждом шаге; лид `calc` приходит в админ-чат с параметрами; при изменении ставки в `taxes.yaml` и перезапуске расчёт меняется без правки кода.

## 6. Фаза 2 — «Проверить объект»

### 6.1. Ввод (на выбор пользователя)

- **Referencia catastral** — 20 символов (принимать и 14-символьную RC участка → показать список объектов на участке для выбора). Валидация формата и контрольных букв.
- **Адрес** — пошагово: муниципалитет (по умолчанию Barcelona), улица (поиск по справочнику улиц Catastro), номер, далее выбор этажа/двери из списка.
- **Геоточка** — отправка локации в Telegram → поиск RC по координатам.

### 6.2. Интеграция Catastro (`/integrations/catastro.py`)

- Открытые сервисы «Consulta de datos catastrales no protegidos» (OVC). Документация: `https://www.catastro.hacienda.gob.es/ws/WCFservices_Consulta.pdf`. Использовать JSON-вариант сервисов (`.../OVCWcfCallejero/COVCCallejero.svc/json/...`), при недоступности — SOAP/XML (`OVCCallejero.asmx`). Нужные методы: по RC (`Consulta_DNPRC`), по адресу (`Consulta_DNPLOC` + справочники улиц), по координатам (`Consulta_RCCOOR`, система координат EPSG:4326).
- Перед реализацией Claude Code сверяет точные имена методов и параметров с PDF-документацией и пишет интеграционный тест на реальном запросе (помечается и запускается отдельно от юнит-тестов).
- Таймаут 10 с, 2 повтора с паузой, кэш ответов по RC на 7 дней (таблица `catastro_cache`).
- Данные Catastro не защищённые — **кадастровой стоимости в них нет**, это нормально.

### 6.3. Вывод

- RC, адрес, назначение (uso), площадь построенная, год постройки, доля в общем имуществе (если есть).
- Ссылка на карточку объекта в Sede Electrónica del Catastro.
- Флаги регулирования из `regulation.yaml`:
  - муниципалитет в списке зон напряжённого рынка → «Аренда ограничена индексом референсных цен» + ссылка на государственный индекс;
  - Барселона → «Новые туристические лицензии не выдаются; действующие планируется прекратить к ноябрю 2028»;
  - год постройки старше порога (по умолчанию 45 лет) → «Проверьте ITE / IEE (техническое обследование здания)».
- Кнопки:
  - 📄 «Заказать nota simple через нас» → лид `nota_simple` с RC и адресом (сами в реестре не заказываем).
  - 🧮 «Рассчитать расходы на покупку» → калькулятор (Фаза 1).
  - 📩 «Хочу консультацию по объекту» → лид `object_check`.

### 6.4. Конфиг `config/regulation.yaml`

```yaml
verified_at: "2026-11-05"
stressed_market_municipalities:   # список муниципалитетов Каталонии; владелец дополняет
  - barcelona
texts:
  stressed_market: { ru: "...", en: "..." }
  tourist_licence_barcelona: { ru: "...", en: "..." }
  ite_check: { ru: "...", en: "..." }
```

Тексты заполняет Claude Code (нейтрально, без юридических гарантий), владелец вычитывает.

**Приёмка Фазы 2:** все три способа ввода находят объект на реальных примерах (не менее трёх адресов в Барселоне); при недоступности Catastro бот отвечает «Сервис кадастра сейчас недоступен, попробуйте позже» и не падает; лид `nota_simple` приходит в админ-чат.

## 7. Фаза 3 — мини-апп «Знаешь ли ты жильё в Барселоне?» (квиз)

> Изменено владельцем 2026-11-06: вместо игры «Угадай цену» — квиз о практике работы с жильём
> в Барселоне/Каталонии/Испании. Первоначальная версия раздела — в истории git.

### 7.1. Механика

- 25 вопросов на игру, 4 варианта ответа, **3 жизни** (каждая ошибка −1; жизни кончились — конец).
- Пул вопросов больше 25 (стартово 44) — каждому игроку случайная подборка; варианты перемешиваются.
- После каждого ответа — правильный вариант и короткое пояснение; где уместно — ссылка на
  инструмент бота (калькулятор / проверка квартиры).
- Одна попытка в день (сутки по `settings.timezone`); незаконченную игру можно продолжить.
- Все числа (вопросов, жизней, попыток, лимиты) — в `settings.yaml` → `quiz`.

### 7.2. Приз и связь с бизнесом

- Прошёл все 25 вопросов с ≥1 жизнью → приз: **бесплатная nota simple**.
- Получение: кнопка в мини-аппе → бот (`?start=prize`) → проверка подписки на канал
  (`quiz.prize_requires_subscription`) → согласие + контакт → лид `game` в админ-чат. Один приз на пользователя.
- Недельный рейтинг — только подписчики канала (подписка проверяется в момент окончания игры).
- «Поделиться результатом» → `t.me/<bot>/<app>?startapp=ref_<user_id>`; приглашённые пишутся как источник.

### 7.3. Вопросы

- Файл `config/quiz.yaml`: id, тема, вопрос, правильный ответ, 3 неверных, пояснение (ru/en),
  необязательный `tool` (calc/check). Правится без программиста, применяется `docker compose restart api`.
- Тексты вычитывает владелец/юрист до запуска (поле `reviewed_at`).

### 7.4. Безопасность

- Правильный ответ **не передаётся** на клиент до ответа; очки считает сервер.
- Авторизация: `initData` Telegram WebApp, HMAC по токену бота, срок жизни ≤ 24 ч.
- Один ответ на вопрос (проверка позиции), ≤ 60 ответов в час на пользователя, лимит попыток в день.
- В рейтинге — только имя и первая буква фамилии из Telegram (без username).

### 7.5. API (FastAPI)

- `GET /api/me` — статус игрока (попытки, лучший результат, приз, подписка, ссылки).
- `POST /api/quiz/start` → `{session_id, total, lives, score, question}` (вопрос без правильного ответа).
- `POST /api/quiz/{id}/answer` `{position, choice}` → `{correct, correct_index, explain, tool, lives, score, finished, next, result?}`.
- `GET /api/leaderboard` → топ-50 недели + место игрока.

### 7.6. Фронтенд и хостинг

- Vite + TypeScript без фреймворков (бандл ≈ 15 KB), мобильная вёрстка, тема из `themeParams`,
  `MainButton`, `BackButton`, `HapticFeedback`, ru/en.
- Домен `barcelona.daagamma.com` (Cloudflare). Порты 80/443 на VPS заняты другими сайтами, поэтому
  вместо Caddy — **Cloudflare Tunnel** (`cloudflared`), HTTPS выдаёт Cloudflare. API и статика
  мини-аппа — один сервис `api`.

**Приёмка Фазы 3:** квиз проходится в Telegram на iOS и Android; подмена initData отклоняется;
правильный ответ не виден в сетевых запросах до ответа; 3 ошибки завершают игру; победитель
получает лид `game` в админ-чат только при подписке на канал; рейтинг недели обновляется.

## 8. Вне рамок этого ТЗ

- Автопостинг в канал.
- Рассылки по базе бота.
- Telegram Stars. (Онлайн-оплата nota simple через Stripe добавлена по решению владельца 2026-11-06.)
- Заказ nota simple в реестре напрямую.
- Расчёт plusvalía municipal и налогов при продаже.
- Интеграция с CRM агентства (только CSV-выгрузка лидов).

## 9. Правила работы для Claude Code

1. Работать строго по фазам; в конце фазы — отчёт и остановка.
2. Если требование ТЗ противоречит технической реальности (например, метод Catastro называется иначе или отдаёт другие поля) — не придумывать обход молча, а описать проблему и предложить вариант.
3. Ставки, пороги и юридические тексты — только в конфиге, никогда в коде.
4. Мелкие осмысленные коммиты с понятными сообщениями на английском.
5. Тесты пишутся вместе с кодом; фаза не закрыта, пока тесты не зелёные.
6. Секреты не попадают в репозиторий, логи и сообщения об ошибках.
7. Все инструкции для владельца (README, DEPLOY) — на русском, пошагово, с командами для копирования и ожидаемым результатом каждого шага.
